## 几个设计决定

**智能体不自己写。** 直接依赖上游 [Eko](https://github.com/FellouAI/eko)（MIT），
系统提示词也用它的，只改了个名字（不改的话它会自称 Eko）。这个项目只做上面那层：
模型接入、任务调度、界面。

**闹钟监听器在 Service Worker 顶层同步注册。** 浏览器休眠后被闹钟唤醒时，
Chrome 可能在任何 await 之前就派发事件，晚注册会漏掉这一次触发。

**任务撞车时排队，不跳过。** 两个任务定在同一分钟很常见，直接丢掉一次的话用户看不出来。

**每次运行开独立的托管窗口。** 把 windowId 钉给智能体，它只在这个窗口里开标签页，
不会抢用户正在用的窗口；跑完自动关。

**开箱检查不花钱。** 服务器是否可用靠拉模型列表判断（这个接口不需要凭证），
凭证是否有效靠本地解 JWT 看过期时间。故意不 POST 一次模型请求去验证，那会真的扣积分。

**设备令牌跟网页登录凭证分开存。** 一个是这台机器的长期身份（配对拿的，只在配对时返回一次），
一个是用户的登录态（会过期）。失效条件和补救办法都不一样，混在一起会互相带坏。

**先做定时领活，再做 WebSocket。** 反过来做很容易写出「WebSocket 一断就不干活」的东西。
在线状态也按心跳算，不看连接：浏览器休眠时连接会悄悄断掉，但设备其实还在。

**闹钟已经排好就不重排。** Service Worker 每次被唤醒都会走一遍排闹钟的逻辑，
每次都重建的话下一次触发时间被一直往后推，极端情况下永远轮不到领活。

**配对不看网页登录凭证。** 一台只用来领活的机器没理由先去网页登录一次。开箱检查放行两种情况：
已经配过对的机器，和在引导页上明说「只让这台机器领活」的。这时聊天和任务页顶上会挂一条提示，
说清楚它们用不了、去哪配。

**拿到租约类错误就把活丢掉，绝不重试。** 20401 / 20402 意味着这个活已经被服务端收回、
多半派给别人了，重试只会把别人干的事搞乱。

## 实测记录

都是在一个临时 Chrome 配置里跑的，任务内容用的是公开网页。

| 测什么 | 结果 |
|---|---|
| 装载 | 扩展管理页显示已启用，无错误；Release 包解压后同样能装 |
| 模型列表 | 从后端拉到可用模型，下拉框正常 |
| 没凭证时 | 一路走到模型请求，401 被翻译成明确报错推回界面，不卡死 |
| 问「你是谁」 | 答「我是 AiToEarn 执行端」 |
| 让它开网页 | 自己规划、开标签页、抓内容、答案正确，Markdown 正常渲染 |
| 建每日任务 | 闹钟立刻排上，任务状态「已启用」 |
| 手动执行 | 成功，23 秒，步骤 deepAction → navigate_to → navigate_to → deepAction |
| 定时触发 | 准点响，成功，20 秒，跑完自动排到明天同一时间 |
| 撞车排队 | 同时触发两个任务，一个 running 一个 queued，先后跑完，没有被丢 |
| 后台被回收 | 关掉 Service Worker 再唤醒，挂着的运行记录变成「中断」，任务状态复位，闹钟重建 |
| 配置引导 | 地址填错提示连不上；没凭证第二步标红；过期凭证提示过期日期；填上有效凭证自动放行 |

## 执行端实测记录（对着线上 pub.flyooo.uk）

| 测什么 | 结果 |
|---|---|
| 配对 | 网页生成配对码 → 填进设备页 → 换到令牌，网页设备列表里出现这台机器，显示插件版本和运行环境 |
| 心跳与在线 | 每 30 秒一次（按服务端返回的间隔），网页显示「在线」，最后心跳时间跟着走 |
| 定时领活 | 网页建 echo 工单，插件的闹钟到点自己领走、执行、回报，网页显示「成功 尝试 1/3」，前后约 20 秒 |
| 后台被回收后还能干活 | 掐掉心跳闹钟等 Service Worker 被回收（目标列表里消失），再建一个 echo 工单：领活闹钟把它唤醒，换了个新的 worker 实例照样领走干完 |
| 重装后自愈 | 扩展重新装上（存储还在），启动时自己补一次心跳、重建闹钟，网页立刻回到在线 |
| 没活可领 | claim 返回空，不报错、不退避，界面上看不到任何异常 |
| 租约对不上 | 用错的 leaseId 回报和续租都被服务端拒（20401）；已完结的工单再回报也是 20401。插件把这几种一律当成「活已经不归我们了」丢掉，不重试 |
| 令牌失效 | 网页上吊销设备后，下一次心跳拿到 20304，插件自己标成「已失效」、清掉全部闹钟、不再发任何请求，界面提示重新配对 |
| 解除配对 | 本地令牌清掉，回到配对表单；服务端那条设备记录还在，要彻底移除得去网页删 |
| 只领活的机器 | 全新配置、本地一个登录凭证都没有：引导页点「只让这台机器领活」→ 配对 → 上线 → 领到 echo 工单干完回报，全程没碰过网页登录。重开侧边栏直接落在设备页，不再被引导页拦；切到聊天页会看到「没有登录凭证」的提示条 |

## 自动化验证的坑

Chrome 137 之后命令行 `--load-extension` 默认被禁，加 `--disable-features=...` 也不一定生效。
可靠的做法是走调试协议：启动带 `--remote-debugging-port` 的临时 Chrome，
再用 CDP 调 `Extensions.loadUnpacked`。
